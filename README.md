# ECHO SHIFT · 错位回声

一款**时间错位**网格解谜游戏。没有战斗，没有道具，没有随机——只有两条规则。

**▶ [在线试玩 · Play now](https://echo-shift-chi.vercel.app)**

![screenshot](docs/screenshot.png)

## 两条规则

> **1. 你走的每一步，会在 N 回合后由一个「回声」原样重演。**
> 回声是实体：它挡路，它踩得住压力板，它撞上你就是时间悖论。
>
> **2. 你每回合都必须移动。没有"原地等待"。**

第二条才是难点所在。因为不能停，**没有人能连续两回合踩住同一块压力板**——
门不会保持开启，它只会**闪一下**：

> **一扇门每被"踩亮"一次，只开一个回合。你必须刚好在那一回合站在门口。**

而且时间也没法白白消耗：想拖延，唯一的办法是**走出去再走回来**，
而你走的这段冤枉路，N 回合后回声会一模一样再走一遍。

### 由此产生的两条硬约束

**奇偶律。** 每走一步，`(x + y) mod 2` 必然翻转。所以你在第 t 回合的位置奇偶性是**锁死的**。
推论一：从压力板到门口的**距离，必须和延迟同奇偶**——差 2 就得绕 2 步，差 1 则**永远无解**。
推论二：延迟为偶数时，回声只可能**踩进你的格子**；延迟为奇数时，它只可能**和你对穿**。
一关会遇到哪种悖论，在它选定延迟的那一刻就决定了。

**回访律。** N 道门串联，就需要 N 次闪门，也就意味着你必须**回到那块板 N 次**，
而且每两次之间的间隔，要正好等于两道门之间的距离。
最后一关 THREE DOORS 就是这样：开局要先在板上来回踩满四次，才能迈出走向第一道门的第一步。

## 玩法

| 操作 | 按键 |
| --- | --- |
| 移动（每回合必须移动） | `↑ ↓ ← →` / `WASD` |
| 撤销 | `Z` / `U` / `Backspace` |
| 重来本关 | `R` |
| 播放最优解 DEMO | `D`，或点 DEMO 按钮；再按一次停止 |
| 切换关卡 | `[` `]` 或点击关卡号 |

手机上滑动屏幕移动。

**看板**：实心暖色方块是「现在的你」；青/品红棋盘抖动的方块是「回声」，角标 `−3` 表示它落后你 3 回合；
四角标记是**回声下一步要去的格子**——所有悖论都可以提前看见，游戏不会阴你。
压力板的指示环画在格子边缘，所以就算有东西站在上面，你依然看得出它是否被踩住。

失败只有两种：**PARADOX**（回声撞上你）和 **STUCK**（四个方向全被堵死，而你又不能不动）。
两种都可以无限撤销。

## 每关都有 DEMO

卡住了就按 **`D`**（或点侧栏的 DEMO 按钮），游戏会**逐步演示这一关的最优解**，
按钮上实时显示进度（`STOP 7/24`），播放期间你的输入会被锁住，再按一次随时停下。

这些演示不是我手写的提示，而是**求解器算出来的最优路线**：
`src/solutions.js` 由 `npm run solutions` 从 BFS 生成，`npm test` 会校验它仍然
最优且仍能通关——关卡一改，测试立刻报 `STALE` 并让你重新生成。

文字版答案在 [`docs/SOLUTIONS.md`](docs/SOLUTIONS.md)（剧透警告），同样是自动生成的。

## 关卡是被证明过的，不是试出来的

`tools/solver.mjs` 是一个跑在**与游戏完全相同的规则引擎**上的广度优先求解器。
`npm test` 对每一关断言四件事：

1. **可解** —— 存在一条通关路线；
2. **最优步数正确** —— 表格里的步数由 BFS 重新算出，改动关卡后如果最优解变了，CI 直接失败；
3. **离开机制就无解** —— 把回声全部移除后，该关必须**变得无解**；
4. **DEMO 的解法没过期** —— 存档的最优解必须仍能通关、且步数仍等于最优。

第 3 条是最重要的：它保证回声机制是**承重的**，而不是装饰。任何一关如果不用回声也能过，测试就红。

最右边的 `states` 是求解器探索过的状态数，也是一个还算诚实的难度代理指标：
第 12 关要搜 47 万个状态才能确定最优解。

## 本地运行

无需安装任何依赖。

```bash
npm run dev        # http://localhost:5173
npm test           # 验证全部关卡（含 DEMO 解法是否过期）
npm run solutions  # 重新生成 src/solutions.js 和 docs/SOLUTIONS.md
npm run solve -- 13 # 打印第 13 关的最优解
```

## 自己加一关

在 `src/levels.js` 里加一个对象，然后 `npm test` 会告诉你它是否成立：

```js
{
  id: 14,
  title: 'YOUR LEVEL',
  delays: [5],        // 一个回声，落后 5 回合；写 [3, 6] 就是两个
  par: 0,             // 先随便填，测试会告诉你真实的最优步数
  hint: 'One line of guidance for the player.',
  grid: [
    '#########',
    '#@..#X..#',
    '#...g...#',
    '#p..#...#',
    '#########',
  ],
}
```

图例：`#` 墙 · `.` 地板 · `@` 你 · `X` 出口 · `p` 压力板 · `g` 闸门。
闸门在**所有**压力板都被实体踩住时开启——所以 N 块板意味着你需要 N 个身体。

加完关卡跑一次 `npm run solutions`，新关的 DEMO 和答案文档会自动补上。

设计关卡时记住那条奇偶律：**板到门口的距离和延迟必须同奇偶**，否则无论怎么走都不可能成立。
`tools/probe.mjs` 可以批量试关，直接告诉你一批候选关卡各自是否可解、最优几步、搜索空间多大。

## 设计笔记

几个刻意的取舍：

- **去掉"等待"是整个设计的转折点。** 有等待时，机制是"你在板上站多久，门就开多久"——
  好懂，但也太软：多站一回合就能救回一个没算准的时机。去掉之后，门变成只闪一回合，
  所有容错消失，玩家被迫**真的去算**回合数和奇偶性。同一批关卡的搜索空间因此涨了一个数量级。
- **回合制而非实时**。解谜的乐趣在于"想明白"，不在于"手速"。回合制还带来完全的确定性，
  这正是求解器能证明关卡的前提。
- **无限撤销**。悖论和失误的惩罚应该是零，玩家才敢去试探规则的边界。
- **只有 4 种元素**（墙、出口、压力板、闸门）。难度全部来自 `延迟`、`距离`、`门的数量`
  这三个数字的相互作用，而不是来自不断堆新机制。第 13 关和第 2 关用的是同一套东西。
- **闸门规则是全局的**（所有板 → 所有门），而不是一板一门。少一条规则，多一层组合。
- **回声不会挡住你的视线**：它下一步的位置永远画在屏幕上。信息完全公开，难的是推理，不是猜。

## 技术

原生 JavaScript + Canvas，ES Modules，零运行时依赖，零构建步骤。
`src/engine.js` 是纯函数、不碰 DOM——浏览器和求解器跑的是同一份代码。

画面是真像素风：每个格子按 8×8 精灵网格绘制，格子尺寸强制为 8 的倍数，
所有坐标取整并关闭抗锯齿，连数字都是代码里自绘的 3×5 位图字。
回声用青/品红**互补相位的棋盘抖动**叠出来——同一个身体，被拆成两个错开的色彩通道。

界面文字为英文。标题字体用 Google Fonts 的 Silkscreen，加载失败会回退到系统等宽字体，
不影响任何功能。
